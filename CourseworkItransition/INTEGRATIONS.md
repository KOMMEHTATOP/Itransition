## Задача 1 — Интеграция с Salesforce ✅ ВЫПОЛНЕНО

> Подробная документация: [SALESFORCE.md](./SALESFORCE.md)

### Суть задачи

Представим, что мы хотим вести CRM-управление пользователями сайта: отправлять маркетинговые рассылки, предлагать дополнительные услуги и т.д. Для этого нужно синхронизировать пользователей сайта с Salesforce.

### Что нужно реализовать

На странице профиля пользователя добавить отдельное действие, доступное только самому пользователю (или администратору). Это действие открывает форму, которая собирает дополнительную информацию о пользователе и создаёт в Salesforce:

- **Account** (организация/компания)
- **Contact**, связанный с этим Account (контактное лицо)

### Шаги реализации

1. Зарегистрировать **Salesforce Developer Org** (бесплатно на developer.salesforce.com)
2. Изучить Salesforce REST API — эндпоинты для создания объектов (`/services/data/vX.X/sobjects/Account`, `/sobjects/Contact`)
3. Настроить **Connected App** в Salesforce для OAuth 2.0 (получить `client_id`, `client_secret`)
4. На **бэкенде** — добавить новый контроллер/эндпоинт, который:
   - Принимает данные формы от пользователя
   - Авторизуется в Salesforce через OAuth 2.0 (Username-Password Flow или Client Credentials)
   - Создаёт Account
   - Создаёт Contact, привязанный к созданному Account
   - Возвращает ссылку или ID созданных объектов
5. На **фронтенде** — на странице профиля добавить кнопку «Добавить в Salesforce», которая:
   - Открывает форму с доп. полями (телефон, компания, должность и т.д.)
   - Отправляет данные на бэкенд
   - Показывает результат (успех / ошибка)

### Что нужно показать на демонстрации

- Заполнение формы на сайте
- Данные появляются в Salesforce (Account + Contact)

### Полезные ресурсы

- [Salesforce Developer](https://developer.salesforce.com) — регистрация Dev Org
- [Trailhead](https://trailhead.salesforce.com) — обучающие материалы
- [Salesforce REST API](https://developer.salesforce.com/docs/atlas.en-us.api_rest.meta/api_rest/)

### Открытые вопросы

- Аккаунта в Salesforce нет — нужно зарегистрировать бесплатный Developer Org
- Каким способом авторизовываться в Salesforce? Скорее всего **Username-Password Flow** (сервер-сервер, один токен для всего приложения) — проще всего для учебного проекта
- Какие поля собирать в форме? Минимальный вариант: телефон, название компании (для Account), должность
- Хранить ли Salesforce ID в базе (чтобы не создавать дубли при повторном нажатии)?

## Задача 2 — Интеграция с Odoo

### Суть задачи

Реализовать двустороннюю интеграцию между курсовым проектом и внешним Odoo-приложением. Odoo выступает как read-only просмотрщик агрегированных данных из инвентарей.

### Часть 1 — API в курсовом проекте

Реализовать внешний API, который:
- Возвращает агрегированные результаты по инвентарю
- Защищён **API-токеном** (токен генерируется отдельно для каждого инвентаря)
- Токен даёт доступ только к данным своего инвентаря

На странице инвентаря добавить ссылку/кнопку, которая возвращает сгенерированный API-токен.

**Агрегированные данные** должны включать:
- Название инвентаря
- Список полей (название поля, тип)
- Для числовых полей: среднее, минимум, максимум
- Для текстовых полей: несколько самых популярных значений

### Часть 2 — Приложение в Odoo

Создать внешнее Odoo-приложение, которое:
- Хранит импортированные инвентари (название, поля, агрегированные результаты)
- Позволяет просматривать список импортированных инвентарей
- Позволяет просматривать детальную информацию по каждому инвентарю
- Имеет действие «Импортировать» — принимает API-токен, делает запрос к курсовому проекту и сохраняет данные

Odoo-приложение работает только на чтение (read-only viewer).

### Опционально (сложно)

Добавить возможность создавать items в Odoo и экспортировать их обратно в курсовой проект.

### Что нужно показать на демонстрации

- Развёрнутый экземпляр Odoo с установленным приложением
- Процесс импорта: вводим API-токен → данные появляются в Odoo

### Полезные ресурсы

- [Odoo Developer](https://www.odoo.com/documentation/17.0/developer.html) — документация
- [Odoo Community Edition](https://github.com/odoo/odoo) — можно поднять локально через Docker

### Открытые вопросы

- Аккаунта и экземпляра Odoo нет — нужно развернуть через Docker (проще всего)
- Где хранить API-токен — в той же БД проекта, новая таблица `InventoryTokens`?
- Odoo-приложение пишется на Python (модули Odoo) — нужно изучить структуру модуля Odoo
- Как развернуть Odoo для демонстрации — локально или на сервере (у проекта уже есть сервер `app.basharov.org`)?

## Задача 3 — Интеграция с Power Automate

### Суть задачи

Реализовать систему тикетов поддержки: пользователь создаёт тикет прямо в приложении, JSON-файл загружается в облако (OneDrive или Dropbox), а Power Automate автоматически рассылает уведомления администраторам.

### Часть 1 — В приложении

Добавить возможность создать тикет поддержки из **любой страницы** приложения:
- Кнопка/иконка «Help» (например, в навбаре или футере) — всегда доступна
- Ссылка «Создать тикет» в футере страницы

При нажатии открывается форма, которая запрашивает:
- **Summary** — краткое описание проблемы (вводит пользователь)
- **Priority** — выбор из: `High`, `Average`, `Low`

Приложение автоматически заполняет остальные поля и генерирует JSON:

```json
{
  "reportedBy": "email или имя текущего пользователя",
  "inventory": "название инвентаря, если тикет создан со страницы инвентаря (иначе null)",
  "link": "URL страницы, с которой пользователь открыл форму",
  "priority": "High | Average | Low",
  "summary": "текст от пользователя",
  "adminEmails": ["admin1@example.com", "admin2@example.com"]
}
```

Сгенерированный JSON загружается напрямую через API в OneDrive или Dropbox.

### Часть 2 — Cloud Flow в Power Automate

Создать автоматический поток в Power Automate:

1. **Триггер** — новый файл появился в папке OneDrive / Dropbox
2. **Читает** содержимое файла как JSON
3. **Отправляет e-mail** каждому адресу из `adminEmails` (через Gmail) с красиво оформленным телом письма и темой, содержащей поля из JSON
4. **Отправляет мобильное уведомление** в приложение Power Automate на телефон (один фиксированный «супер-админ» аккаунт)

### Что нужно показать на демонстрации (видео)

- Пользователь заполняет форму тикета
- Файл загружается в OneDrive/Dropbox
- Flow запускается в Power Automate
- Письма приходят на почту администраторов
- На телефоне приходит push-уведомление (запись экрана телефона)

### Полезные ресурсы

- [Power Automate](https://make.powerautomate.com) — создание flows (нужен Microsoft аккаунт)
- [OneDrive API](https://learn.microsoft.com/en-us/onedrive/developer/rest-api/) — загрузка файлов
- [Dropbox API](https://www.dropbox.com/developers/documentation/http/documentation) — альтернатива
- [Power Automate mobile](https://apps.apple.com/app/power-automate/id1094928825) — приложение для уведомлений

### Открытые вопросы

- OneDrive или Dropbox? OneDrive проще связать с Power Automate (оба от Microsoft), но нужен Microsoft аккаунт. Dropbox — нужен отдельный коннектор.
- Нет аккаунтов: Microsoft (для Power Automate + OneDrive) и Gmail (для отправки писем) — нужно зарегистрировать
- `adminEmails` — брать динамически из БД (список всех admin-пользователей) или хардкодить в конфиге?
- Где разместить кнопку Help — в навбаре (всегда видна) или только в футере?
